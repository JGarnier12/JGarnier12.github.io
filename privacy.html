Privacy Policy

ServiceFuze Backup Utility · last updated 23 October 2026

1. What this utility is

The ServiceFuze Backup Utility is a privately operated set of scripts run on a single personal computer by a single person. That person is its operator and its only user. It is not a product, not a service, and is not made available to anyone else. There is no sign-up and there are no accounts other than the operator's own.

Its purpose is to keep encrypted off-machine copies of the operator's own software development repository, so that a computer failure does not destroy work that exists nowhere else.

2. The Google permission it requests, and what that permission allows

It requests exactly one Google OAuth scope:

https://www.googleapis.com/auth/drive.file

This is Google's per-file scope. It grants access only to files this utility itself creates. Consequently this utility:

  • cannot list, read, download, modify or delete any other file in the Google Drive account — including documents, photos, and backups made by other means;
  • cannot read file or folder names outside what it created;
  • cannot access Gmail, Contacts, Calendar, Photos or any other Google service.

No broader scope is requested, and none is needed.

3. What it stores in Google Drive

In a single folder that it creates for itself, and nowhere else:

FileWhat it is
servicefuze-<timestamp>-<label>.tar.gz.age An encrypted archive of the operator's own development repository.
…​.tar.gz.age.sha256 A checksum, used to verify the upload arrived intact.
…​.meta.tar.gz.age An encrypted copy of the repository's version-control metadata.

The archive contains the operator's own source code, configuration and development documentation. It is not a service that collects information from other people, and it does not gather any information from visitors to these pages.

4. Encryption

Every archive is encrypted on the operator's computer before it is uploaded, using age with an X25519 key pair.

The scheduled backup holds only the public half of that key pair, so the process that creates and uploads archives has no ability to decrypt them. The private half is kept separately by the operator, in the operator's own password store and in an offline copy. It is never given to Google, never placed in Google Drive, never written to this utility's logs or reports, and is never available to the scheduled process that performs the uploads.

The practical effect: the contents of these archives are not readable by Google, nor by anyone who obtains access to the Google Drive accounts, nor by anyone who obtains the backup computer's scheduled task.

5. Credentials

  • No Google password is ever requested, seen, stored or transmitted by this utility. Sign-in happens on Google's own pages.
  • Authorisation is held as an OAuth refresh token stored locally in the operator's own configuration file, readable only by the operator's user account.
  • Tokens are never sent anywhere except to Google, and are never written to logs or reports.
  • Authorisation can be withdrawn at any time by the operator at myaccount.google.com/permissions, which immediately prevents any further access.

6. How long files are kept

The intended retention is seven daily, four weekly and three monthly recovery points in each account. Expiry only ever considers files that this utility itself created and named, inside its own folder; anything else in the account is outside what it can see or act on.

At the time of writing, automatic deletion of remote files is disabled, so nothing is removed from either Google Drive account without the operator doing it deliberately.

7. Sharing

Nothing is shared with anyone. There are no third-party processors, no analytics, no advertising, and no transfer of data to any party other than Google Drive acting as the operator's own storage. These pages themselves set no cookies, load no third-party resources, and run no scripts.

8. Changes

If what this utility does changes materially, this page will be updated and the date above revised.
